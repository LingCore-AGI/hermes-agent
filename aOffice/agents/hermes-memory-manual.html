1记忆系统总览官方文档

Hermes Agent 拥有有界、经过整理的持久化记忆，可跨会话保存。这使 Agent 能够记住用户偏好、项目环境、工作约定以及已学到的经验知识。

记忆系统的核心设计原则：

  • 有界性：严格的字符上限，强制 Agent 进行信息筛选与压缩，只保留最重要的知识
  • 冻结快照：每次会话开始时从磁盘加载一次，注入系统 prompt，会话中途不变更，以保留 LLM 前缀缓存提升性能
  • 手动整理：Agent 自主决定什么该记、什么该忘，通过 memory 工具管理记忆条目
  • 安全防护：记忆条目在写入前经过安全扫描，防止 prompt 注入和数据外泄
信息记忆系统的两个核心文件是 MEMORY.md（Agent 个人笔记）和 USER.md（用户档案），均存储在 ~/.hermes/memories/ 目录下。
🔎 代码排查结果 整体：代码证实
  • 有界性：字符上限 2,200 / 1,375 为代码常量，见 tools/memory_tool.py 的 MemoryStore 默认参数与 hermes_cli/config_defaults.py:1770-1771（注释明确标注 "≈800 tokens at 2.75 chars/token"）。
  • 冻结快照：会话开始注入一次、写盘即时但 prompt 不变 —— agent/system_prompt.py（memory 块进入 volatile 段但仅随 prompt 重建刷新）与 tools/memory_tool.py 的 load_from_disk / save 逻辑证实。
  • 手动整理 + 安全防护：add/replace/remove 三操作与 threat_patterns 安全扫描（scope="strict"）均在 tools/memory_tool.py 中实现。
  • 两文件路径：MEMORY.md 与 USER.md 位于 get_hermes_home()/memories/，见 tools/memory_tool.py。
  • 源码新发现：memory 工具还支持 batch 批量操作 参数与 write approval 审批门（config_defaults.py:1757-1768 的 memory.write_approval，默认 false；开启后写入需经 /memory approve），本手册此前未记载。

2.1 存储位置（Windows / macOS / Linux）

Hermes 桌面版的"记忆"和"学习经验"，都储存在你电脑上的一个本地文件夹里。这个文件夹的位置取决于你的操作系统：

  • Windows 系统：%LOCALAPPDATA%\hermes（即 C:\Users\<用户名>\AppData\Local\hermes\）
  • macOS / Linux 系统：~/.hermes
提示这是一个隐藏文件夹，你可以在文件管理器的地址栏直接输入路径访问。记忆和学习经验相关的核心文件，都存放在这个主目录下的 memories 文件夹中。

3记忆是如何工作的DeepSeek 对话

3.1 加载与生效

每次开始新会话，Hermes 会读取 MEMORY.md 和 USER.md 的内容，像"快照"一样固定在本次对话的系统提示词中。

3.2 "延迟生效"原则

会话中，Hermes 通过 /learn 指令或 memory 工具修改记忆文件是实时保存的。但这些更改要等到下一次新会话开始时才会生效。这是为了保持对话的稳定性，避免上下文混乱。

3.3 自我管理与学习

当你完成一个任务后输入 /learn，Hermes 会将其提炼成一条新的技能或知识，存入 ~/.hermes/skills/ 文件夹的 SKILL.md 文件中。此外，Hermes 还会扫描项目目录下的 .hermes.md、AGENTS.md 等文件作为上下文。

3.4 会话记录

你与 Hermes 的所有聊天记录，都存储在 ~/.hermes/state.db 这个 SQLite 数据库文件中。

🔎 代码排查结果 3 项证实，1 项证伪
  • 3.1 加载与生效：证实。会话开始由 agent_init.py:1766（load_from_disk()）加载，注入系统 prompt（agent/system_prompt.py:745-754）。
  • 3.2 延迟生效：证实。写盘即时（memory_tool 每次 add/replace/remove 后保存），prompt 快照不变，下一会话重新加载。
  • 3.3「通过 /learn 修改记忆文件」：证伪。/learn 的职责是生成 Skill（agent/learn_prompt.py:1-27 模块 docstring：把用户描述提炼成可复用技能，经 skill_manage 写入 skills 目录），不写 MEMORY.md / USER.md。记忆更新只经 memory 工具。
  • 3.3 扫描 .hermes.md / AGENTS.md：证实。上下文文件清单含 SOUL.md、.hermes.md、AGENTS.md、CLAUDE.md、.cursorrules（agent/agent_init.py:613、agent/prompt_builder.py:2130）。
  • 3.4 state.db：证实（hermes_state.py:348）。

4记忆在系统 Prompt 中的呈现方式官方文档

每次会话开始时，记忆条目从磁盘加载，以冻结块的形式渲染到系统 prompt 中：

══════════════════════════════════════════════
MEMORY (your personal notes) [67% — 1,474/2,200 chars]
══════════════════════════════════════════════

User's project is a Rust web service at ~/code/myapi using Axum + SQLx

§

This machine runs Ubuntu 22.04, has Docker and Podman installed

§

User prefers concise responses, dislikes verbose explanations

格式说明：

  • 标头：显示存储类型（MEMORY 或 USER PROFILE）
  • 使用百分比和字符计数：让 Agent 了解当前容量使用情况
  • 条目分隔符：以 §（节符）分隔各条目
  • 多行支持：条目可以是多行文本
冻结快照模式系统 prompt 注入在会话开始时捕获一次，会话中途不会改变。这是有意为之 — 目的是保留 LLM 的前缀缓存以提升性能。当 Agent 在会话期间添加或删除记忆条目时，更改会立即持久化到磁盘，但要到下一次会话开始时才会出现在系统 prompt 中。工具响应始终显示实时状态。
🔎 代码排查结果 整体：代码证实
  • 标头格式 MEMORY (your personal notes) [67% — 1,474/2,200 chars] 与 USER PROFILE (who the user is)：tools/memory_tool.py 的 format_for_system_prompt() 逐字实现，含百分比与字符计数。
  • 条目分隔符 §（节符）：代码常量 ENTRY_DELIMITER = "\n§\n"（tools/memory_tool.py）。
  • ═×46 分隔线、多行条目支持：同上文件证实。
  • 冻结快照说明：与 agent/system_prompt.py 的缓存设计注释一致（stable/volatile 分层，memory 位于 volatile 段但仅随 prompt 重建刷新）。

5Memory 工具操作官方文档

5.1 三种操作：add / replace / remove

操作功能示例
add 添加新的记忆条目 memory(action="add", target="memory", content="...")
replace 用更新内容替换现有条目（子字符串匹配） memory(action="replace", target="memory", old_text="...", content="...")
remove 删除不再相关的条目（子字符串匹配） memory(action="remove", target="memory", old_text="...")
注意没有 read 操作。记忆内容在会话开始时自动注入系统 prompt，Agent 将其作为对话上下文的一部分来查看。 
# 添加环境事实到 memory
memory(action="add", target="memory",
       content="This machine runs Ubuntu 22.04, has Docker and Podman installed")

# 添加用户偏好到 user
memory(action="add", target="user",
       content="User prefers concise responses, dislikes verbose explanations")

# 如果记忆中包含 "User prefers dark mode in all editors"
memory(action="replace", target="memory",
       old_text="dark mode",
       content="User prefers light mode in VS Code, dark mode in terminal")

# 删除包含特定子字符串的条目
memory(action="remove", target="memory",
       old_text="staging server SSH port")

5.2 子字符串匹配机制

replace 和 remove 操作使用简短的唯一子字符串匹配 — 不需要完整的条目文本。old_text 参数只需是能唯一标识某一条目的子字符串即可。

错误处理如果子字符串匹配到多个条目，则返回错误，要求提供更具体的匹配内容。
🔎 代码排查结果（第 5 章） 整体：代码证实
  • add / replace / remove 三操作及参数签名（action / target / content / old_text）：tools/memory_tool.py 工具 schema 完整定义。
  • 「没有 read 操作」：证实。工具 schema 中无 read action，内容靠系统 prompt 注入。
  • 子字符串唯一匹配、多匹配返回错误：证实（匹配计数 >1 时报错并提示提供更具体的子串）。
  • 源码新发现：工具还接受批量操作参数（batch add/replace/remove），一次调用处理多条，手册此前未记载。

6两个记忆目标说明（memory vs user）官方文档

6.1 memory — Agent 的个人笔记

用于 Agent 需要记住的环境、工作流及经验教训相关信息：

  • 环境事实：操作系统、工具、项目结构
  • 项目约定和配置：代码风格、测试命令、CI 配置
  • 工具怪癖与变通方法：发现的非标准行为及解决方案
  • 已完成任务的日记条目：如"2026-01-15 将数据库从 MySQL 迁移到 PostgreSQL"
  • 有效的技能和技术：验证过的工具用法

6.2 user — 用户档案

用于记录用户的身份、偏好和沟通风格：

  • 姓名、角色、时区
  • 沟通偏好：简洁 vs 详细、格式偏好
  • 反感的事项和需要避免的内容
  • 工作流习惯
  • 技术水平

8.1 记忆已满时的处理

Agent 应当执行以下步骤：

  1. 读取当前条目（显示在错误响应中）

  4. 然后 add 新条目
最佳实践当记忆使用率超过 80%（在系统 prompt 标头中可见）时，在添加新条目之前先整合现有条目。例如，将三个独立的"项目使用 X"条目合并为一个综合性的项目描述条目。

13.1 核心概念总览（Profile → Session / Project）

Hermes 桌面版的配置遵循一种 "配置档案 (Profile) → 会话 (Session) / 项目 (Project)" 的层级结构。你可以把它想象成一个多用户操作系统：

  • 在每个账户下，你可以开启不同的会话 (Session) 或创建项目 (Project)，它们就像是在这个账户下打开的不同任务窗口或工作区。

这种设计的核心目的，是让你能为不同的工作场景（如编程、写作、研究）创建完全隔离且专用的 AI 助手分身。

13.2 配置档案 (Profile) — 你的 AI "分身"

它是什么？

配置档案是一个完全独立的 Hermes 运行环境。你可以把它理解为创建一个全新的 AI "分身"或"角色"。每个分身都拥有自己独立的：

  • 身份与人格（SOUL.md）
  • 配置与密钥（config.yaml、.env）
  • 长期记忆（memories/ 文件夹）
  • 技能（skills/ 文件夹）
  • 会话历史（sessions/ 数据库）
  • 定时任务（cron/）

它的作用？

创建不同的 Profile 可以让你在一台电脑上运行多个互不干扰的 Agent。例如，你可以创建一个 coder Profile 专门用于编程，一个 writer Profile 专门用于写作。它们各自记住各自的上下文、API 密钥和偏好，不会互相混淆。

它体现在哪个文件夹？

默认的 Profile 被称为 default，其根目录位于：

  • Windows: %LOCALAPPDATA%\hermes
  • macOS/Linux: ~/.hermes

当你通过设置界面或命令行（hermes profile create <name>）创建新的 Profile 时，系统会在默认根目录下创建一个名为 profiles/<你的配置档案名> 的新文件夹。

例如，如果你创建了一个名为 my-profile 的配置档案，其完整路径将是：

  • Windows: %LOCALAPPDATA%\hermes\profiles\my-profile\
  • macOS/Linux: ~/.hermes/profiles/my-profile/
注意"新建配置档案"界面正是用于创建这样一个全新的独立环境。其中，"克隆来源"选项允许你从现有 Profile（如 default）复制配置，快速生成一个新分身。

13.3 人格 (Personality) 与 SOUL.md — 分身的"灵魂"

它是什么？

SOUL.md 是一个 Markdown 文件，它定义了你的 Hermes Agent 的核心身份、语气、沟通风格和价值观。它是系统提示词（System Prompt）中的第一项内容，直接决定了 AI "是谁"以及"如何回应"。

它的作用？

它就是你在"对话"模块中看到的"人格设定"。通过编辑 SOUL.md，你可以让 Hermes 从一个通用助手，转变为一个"务实的高级工程师"、"耐心的教师"或"严格的审阅者"。这种人格设定是持久化的，会应用于该 Profile 下的所有会话。

它体现在哪个文件夹？

  • 默认 Profile:
    • Windows: %LOCALAPPDATA%\hermes\SOUL.md
    • macOS/Linux: ~/.hermes/SOUL.md
  • 自定义 Profile（例如 my-profile）:
    • Windows: %LOCALAPPDATA%\hermes\profiles\my-profile\SOUL.md
    • macOS/Linux: ~/.hermes/profiles/my-profile/SOUL.md
注意"配置档案"设置页面的下半部分通常显示 SOUL.md 的内容预览，并提供"保存 SOUL.md"的按钮，这证实了 SOUL.md 是每个 Profile 的核心组成部分。

13.4 记忆与上下文 (Memory & Context) — 分身的"长期经验"

它是什么？

这是 Hermes 跨会话保持"学习经验"和"长期记忆"的机制。它主要由两个文件构成：

文件用途字符上限类比
MEMORY.md记录环境事实、项目约定、已学到的解决方案等2,200 字符"工作笔记本"

它体现在哪个文件夹？

  • 默认 Profile:
    • Windows: %LOCALAPPDATA%\hermes\memories\
    • macOS/Linux: ~/.hermes/memories/
  • 自定义 Profile（例如 my-profile）:

    • macOS/Linux: ~/.hermes/profiles/my-profile/memories/

13.5 项目 (Project) 与会话 (Session) — 分身的"具体任务"

它们是什么？

  • 会话 (Session)：是你与一个特定 Profile 下的 Agent 进行的单次对话。所有会话记录都存储在 Profile 目录下的 state.db 数据库文件中。
  • 项目 (Project)：是一个更高层次的工作区概念。创建项目时，你可以为其命名、关联一个或多个本地文件夹，并记录"想法"（这会被保存为 IDEA.md 文件）。

它们的作用？

  • 会话用于处理具体的、临时的对话任务。
  • 项目则用于将一组相关的会话、文件和长期目标组织在一起。它为 AI 提供了一个更广阔的上下文背景。

它们体现在哪个文件夹？

  • 会话历史：存储在 state.db 文件中，位置在 Profile 根目录下。
    • 默认: %LOCALAPPDATA%\hermes\state.db 或 ~/.hermes/state.db
  • 项目文件：项目的核心定义文件（如 IDEA.md）通常存放在你为项目指定的工作区（Workspace）文件夹中。这个工作区文件夹可以位于你电脑上的任何位置，但习惯上可以放在 Profile 目录下的 workspace/ 文件夹内。
    • 默认工作区: %LOCALAPPDATA%\hermes\workspace\ 或 ~/.hermes/workspace/

第 1 级
最高权重
"宪法"SOUL.md

是否自动更新：否（仅用户手动设置）

冲突处理规则：绝不被覆盖。即使 Memory 说"用户喜欢简短"，如果 Soul 说"必须详细解释"，AI 会优先遵守 Soul。

第 2 级
"用户档案"USER.md

核心职责：定义"我是谁"（用户的背景、沟通偏好、个人习惯）。

是否自动更新：是（AI 自动学习/积累）

冲突处理规则：覆盖 Memory 的泛化知识。例如 Memory 说"通用方案是 A"，但 User 说"我讨厌方案 A"，AI 会听 User 的。

第 3 级
"工作日志/项目笔记"MEMORY.md

核心职责：定义"我们做过什么"（当前项目的技术栈、已知的 Bug 解决方案、已定的架构约定）。

是否自动更新：是（AI 自动学习/积累）

最低/临时

核心职责：定义"这个具体项目要干嘛"（当下的目标、这次会话的核心任务）。

是否自动更新：否（用户新建项目时手动填写）

冲突处理规则：仅作为上下文补充。如果 Idea 说"今天重构登录页"，但 Memory 说"登录页已废弃"，AI 会优先听 Memory 的既定事实。

16.3 拼装逻辑（入锅顺序）

当你新建一个会话时，Hermes 的"大脑"是按照以下顺序"吃"进去这些信息的：

  1. 先吃 SOUL.md（定义基调：你是一个严谨的工程师，不允许胡扯）。
  2. 再吃 USER.md（套用滤镜：用户喜欢带代码示例的回答，讨厌废话）。
  3. 接着吃 MEMORY.md（填充背景：当前仓库用的是 Python 3.11，数据库是 PostgreSQL）。
  4. 最后吃 IDEA.md 和当前的 Prompt（下达指令：现在，请帮我修复这个登录接口的超时问题）。
结果AI 会以"严谨工程师（Soul）"的身份，用"带代码示例（User）"的风格，基于"Python 3.11 和 PostgreSQL（Memory）"的技术事实，去完成"修复登录超时（Idea）"的任务。

19总结

19.1 记忆系统核心（官方文档）

  • Hermes Agent 的记忆系统由 MEMORY.md（Agent 笔记，2,200 字符）和 USER.md（用户档案，1,375 字符）两个核心文件构成，位于 ~/.hermes/memories/ 目录下。
  • Agent 通过 memory 工具自主管理记忆条目（add / replace / remove），在每次会话开始时以冻结快照形式注入系统 prompt。
  • 重复条目自动拒绝；记忆写入前经过安全扫描（防 prompt 注入 / 凭据外泄）。
  • state.db 存储所有会话历史以供 FTS5 全文搜索（session_search）。

19.2 桌面版配置层级（DeepSeek 对话）

  1. 配置档案 (Profile) 是最顶层的隔离单位，相当于一个独立的 AI 分身。
  2. 每个 Profile 通过 SOUL.md 定义其独特的人格（宪法级，绝不被覆盖）。
  3. 通过 USER.md（用户档案，第 2 级）和 MEMORY.md（工作日志，第 3 级）实现跨会话的长期记忆。
  4. 在 Profile 之下，你可以创建不同的会话来处理具体任务，或创建项目（IDEA.md，第 4 级）来组织更大的工作。
